# CineXplorer Log Files

This directory contains log files generated by the CineXplorer application during development and production.

## Log File Structure

### Current Log Files

- **cinexplorer.log** - Main application logs (requests, business logic, errors)
- **django.log** - Django framework warnings and errors
- **requests.log** - HTTP request/response logging with correlation IDs
- **database.log** - Database query logs with performance monitoring
- **errors.log** - Application errors with full stack traces
- **frontend.log** - Development-only frontend console/logger capture (browser logs forwarded via API)

### Rotated Log Files

The system automatically rotates log files when they reach 10MB. Rotated files follow the pattern:

- `filename.log.1` - Most recent backup
- `filename.log.2` - Second most recent backup
- `filename.log.3` - Third most recent backup
- etc.

**Backup Retention:**

- Standard logs: 5 backup files (55MB total per log type)
- Error logs: 10 backup files (110MB total)

## Log Levels

- **DEBUG** - Detailed information for development and troubleshooting
- **INFO** - General application flow and important events
- **WARNING** - Potential issues that don't prevent operation
- **ERROR** - Error conditions that should be investigated
- **CRITICAL** - Serious errors that may cause application failure

## Performance Monitoring

Database queries are automatically categorized by performance:

- **Fast queries** (< 100ms): DEBUG level
- **Slow queries** (100-500ms): INFO level
- **Warning queries** (500ms-2s): WARNING level  
- **Critical queries** (> 2s): CRITICAL level

## Viewing Logs

### Real-time Monitoring

```bash
# View main application logs
docker-compose exec backend tail -f logs/cinexplorer.log

# View database query logs
docker-compose exec backend tail -f logs/database.log

# View error logs only
docker-compose exec backend tail -f logs/errors.log

# View all logs combined
docker-compose exec backend tail -f logs/*.log
```

### Searching Logs

```bash
# Search for specific patterns
docker-compose exec backend grep "ERROR" logs/cinexplorer.log

# Search for slow queries
docker-compose exec backend grep "SLOW QUERY" logs/database.log

# Search across all logs
docker-compose exec backend grep -r "search_term" logs/

# View logs from specific time period (last hour)
docker-compose exec backend find logs/ -name "*.log" -exec grep "$(date -d '1 hour ago' '+%Y-%m-%d %H')" {} \;
```

### Log Analysis

```bash
# Count error occurrences
docker-compose exec backend grep -c "ERROR" logs/cinexplorer.log

# View most recent errors
docker-compose exec backend grep "ERROR" logs/errors.log | tail -10

# Database performance analysis
docker-compose exec backend grep "SLOW QUERY" logs/database.log | cut -d'(' -f2 | cut -d')' -f1 | sort -n
```

## Configuration

Log behavior is controlled by environment variables:

- `DEBUG=True` - Enables detailed logging to console and files
- `DJANGO_LOG_LEVEL=DEBUG|INFO|WARNING|ERROR|CRITICAL` - Override file log level
- `DJANGO_CONSOLE_LOG_LEVEL=DEBUG|INFO|WARNING|ERROR|CRITICAL` - Override console log level (separate from files)
- See `config/logging.py` for detailed configuration

### Console vs File Logging Levels

The logging system supports independent control of console and file logging levels:

**Console Logging (`DJANGO_CONSOLE_LOG_LEVEL`):**

- **Development default:** INFO (reduces noise from third-party libraries)
- **Production default:** WARNING (minimal console output)
- **Health checks:** Automatically filtered from console output
- **Third-party libraries:** Suppressed or limited (watchdog, debug_toolbar, etc.)

**File Logging (`DJANGO_LOG_LEVEL`):**

- **Development default:** DEBUG (comprehensive logging for analysis)
- **Production default:** INFO (detailed but not excessive)
- **Health checks:** Preserved in files for monitoring
- **Third-party libraries:** Full logging preserved

### Common Configuration Examples

```bash
# Development: Quiet console, verbose files
DJANGO_CONSOLE_LOG_LEVEL=INFO
DJANGO_LOG_LEVEL=DEBUG

# Debug mode: Verbose console and files
DJANGO_CONSOLE_LOG_LEVEL=DEBUG
DJANGO_LOG_LEVEL=DEBUG

# Production: Minimal console, important events in files
DJANGO_CONSOLE_LOG_LEVEL=WARNING
DJANGO_LOG_LEVEL=INFO

# Troubleshooting: Silent console, maximum detail in files
DJANGO_CONSOLE_LOG_LEVEL=ERROR
DJANGO_LOG_LEVEL=DEBUG
```

## Storage Management

**Total Estimated Storage:** ~330MB maximum for all log files

**Automatic Cleanup:**

- Log rotation occurs automatically when files reach 10MB
- Old log files are automatically removed beyond retention limits
- No manual cleanup required under normal operation

## Docker Integration

The logs directory is mounted as a Docker volume, making logs accessible from both:

- **Container path:** `/backend/logs/`  
- **Host path:** `C:\dev\CineXplorer\backend\logs\`

Log files persist between container restarts and are accessible for analysis on the host system.

## Security Notes

- Log files may contain sensitive information in development mode
- Production logs exclude personal data and API keys
- Log files should be included in `.gitignore` (not committed to version control)
- Regular cleanup may be needed in long-running development environments
